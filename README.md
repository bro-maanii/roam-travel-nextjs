# Roam — Travel Agency Website

A complete frontend technical assessment built with **Next.js App Router, TypeScript, Tailwind CSS 4, and GSAP**. Roam pairs an editorial travel aesthetic with practical, accessible booking discovery.

## Project links

- **GitHub:** https://github.com/bro-maanii/roam-travel-nextjs
- **Live website:** https://roam-travel-nextjs.vercel.app
- **Upload-ready submission:** [Roam Assessment Submission (PDF)](submission/Roam-Assessment-Submission.pdf)

## Run locally

Requires **Node.js 22.13+** and npm. Travel searches work locally without API keys or a database. The contact form uses a server-side email provider configured with environment variables.

```bash
npm ci
npm run dev
```

Open http://localhost:3000. For a production build:

```bash
npm run build
npm start
```

## Features

- Four working service forms: **flights, hotels, visa assistance, and car rental**.
- Deterministic, locally generated results based on the selected destination, dates, and traveler count.
- Flight quotes price the whole party; hotel quotes account for nights and two guests per room; rental quotes account for days and vehicle capacity; visa service fees account for applicants.
- Required fields, future-date validation, date range validation, and party size limits.
- Six destinations with regional filters, expanded browsing, session-only saved favorites, and accessible trip detail dialogs.
- Search results and destination packages feed a prefilled enquiry into the contact form.
- Contact form with client/server validation, loading and failure states, Resend or SMTP delivery, and a separate thank-you page after a confirmed send.
- Responsive mobile, tablet, and desktop layouts with a mobile navigation menu.
- GSAP hero entrance, ScrollTrigger reveals, animated statistics, and card/image hover effects.
- Reduced-motion support, semantic landmarks, keyboard-operable tabs, visible focus styles, a skip link, native modal focus handling, and meaningful image descriptions.
- Per-page titles and descriptions, canonical URLs, a generated social-share image, full favicon set, robots.txt, and sitemap.xml.
- Organization, website, service and FAQ structured data, using the same FAQ content shown on the page.
- Custom 404, route loading/error screens, privacy policy and terms pages.
- Sticky mobile contact CTA, a privacy preference banner, and consent-gated Vercel Web Analytics.

**Sample travel data:** Prices, availability, testimonials, profiles, statistics, and packages are illustrative. The website does not create reservations, collect payments, or submit visa applications. Contact enquiries are emailed when a provider is configured; otherwise an error and direct email link are shown. Form contents are not saved to an application database. Favorites reset on reload.

## Contact email setup

All enquiries are delivered to **emanaliabbasi99@gmail.com**. The contact location is **Karachi, Pakistan**. Copy `.env.example` to `.env.local` for local development; add the same values to the Vercel project's Production environment for deployment. Never prefix secrets with `NEXT_PUBLIC_`.

Choose one provider:

- **Resend:** set `RESEND_API_KEY` and `CONTACT_FROM_EMAIL` to an authorized sender for that account (normally a verified domain).
- **SMTP:** set `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, and `CONTACT_FROM_EMAIL`. Port 465 uses implicit TLS; other ports require STARTTLS. Use an app password or service credential where the provider requires it.

The visitor's address is used as Reply-To, and the recipient is fixed on the server. If the provider rejects a request, the form retains the visitor's details and does not redirect to the thank-you page. The endpoint validates the origin, body size and fields, uses a honeypot, and has a best-effort per-instance request limit. Use host-level rate limits for distributed abuse protection.

## Search visibility and analytics

The canonical origin is configured in `src/lib/site.ts`; update it when changing domains. `/robots.txt` and `/sitemap.xml` are generated by App Router metadata routes. Thank-you and 404 pages are excluded from indexing. JSON-LD describes the actual site and visible FAQ; it does not publish fictional reviews or company statistics as verified structured data. These features help content discovery and interpretation; rankings or inclusion in generated answers are not guaranteed.

Vercel Web Analytics must be enabled for the project. The SDK loads only after analytics consent; URL query strings, fragments and form contents are excluded from tracking. Visitors can choose essential features only or reopen preferences from the footer. A browser preference is retained for 180 days. Analytics is not required to search or send an enquiry.

## Try the site

1. Choose a service, destination, future date, and traveler count; submit **Let’s explore**.
2. For hotels and car rentals, choose an end date after the start date.
3. Click **Enquire** on a result to populate the contact form.
4. Filter destinations by region, save a favorite, or open a destination for package details.
5. With email delivery configured, submit a valid contact form to reach the thank-you page. Without credentials, use the displayed email link.

## Structure

```text
src/
  app/                  # App Router entry point, metadata, design tokens and styles
  components/
    brand.tsx           # Shared wordmark
    header.tsx          # Desktop and mobile navigation
    home.tsx            # Page composition and shared enquiry state
    motion.tsx          # Scoped GSAP animations and cleanup
    search-panel.tsx    # Service tabs, forms and mock result cards
    destinations.tsx    # Regional browsing, favorites and trip modal
    contact.tsx         # Enquiry form, success state and FAQ
  lib/travel-data.ts    # Typed sample data, search validation and quote calculations
public/                 # Bundled photography and favicon
tests/
  search.test.ts        # Quote calculation and validation tests
  e2e/travel.spec.ts    # Browser workflows, responsive and accessibility checks
```

The visual system uses warm ivory, forest green, lime accents, sans-serif text, and italic serif headings. Tailwind utilities and `@apply` are combined with reusable, token-based CSS classes for the editorial layouts.

## Verification

```bash
npm run typecheck
npm test
npm run build

# Install the browser once, then run browser tests against a production build:
npx playwright install chromium
npm run test:e2e
```

Playwright starts a local production server on port 3001. The suite checks all service searches, enquiry handoff, destination filtering and saving, modal behavior, contact validation, mobile navigation, keyboard tabs, horizontal overflow at 320/390/768/1024/1440px, runtime errors, and automated accessibility rules. It also saves desktop and mobile screenshots to `artifacts/`.

To test an existing deployment instead:

```powershell
$env:PLAYWRIGHT_BASE_URL="https://your-deployment.vercel.app"
npm run test:e2e
```

Use `npm run format` to format project files.

## Deploy to Vercel

Import the GitHub repository into Vercel, select the **Next.js** framework preset, add your mail delivery environment variables, and deploy. Search and content pages build without secrets. Alternatively, use the Vercel CLI:

```bash
npx vercel --prod
```
